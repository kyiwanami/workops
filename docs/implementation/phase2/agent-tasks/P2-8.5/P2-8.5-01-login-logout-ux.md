# P2-8.5-01 login / logout UX completion

## 目的

P2-5 / P2-6 で成立した Cognito Hosted UI login と PLATFORM / TENANT App Client 分離を前提に、Cognito Hosted UI 上で入口を判別でき、ログイン済みユーザーが WorkOps 画面から logout できる状態にする。

## ユーザー要求

- ログアウト導線を作る
- Spring Security logout 設定を行う
- Cognito logout URL と連携する
- logout 後は意図した入口へ戻す
- Cognito Hosted UI の PLATFORM / TENANT login 入口の見た目差分を作る
- CloudFront 経由で login / logout 動作確認できるようにする
- 本格的なブランドデザイン、テナント別ログイン画面、SSO 前提の導線は作らない

## 前提

- `/login/platform` は `/oauth2/authorization/platform` へ進む
- `/login/tenant` は `/oauth2/authorization/tenant` へ進む
- `/login` は通常利用者向けの TENANT login 開始画面として維持する
- App Client の allowed sign-out URL は CloudFront HTTPS URL の `/login` を使う
- `users.actor_type` と `permission_sets` を業務利用者・業務権限の正本として維持する
- 既存データ移行と後方互換性は考慮しない

## 案

- 画面の logout は CSRF token 付き `POST /logout` に固定する
- Spring Security の local logout 完了後、WorkOps 専用 `LogoutSuccessHandler` で Cognito Hosted UI の `/logout` へ redirect する
- Cognito logout URL は `client_id` と `logout_uri` のみを渡す
- `LoginUserContext.actorType()` が `PLATFORM` の場合は PLATFORM App Client ID、`TENANT` の場合は TENANT App Client ID を使う
- `Authentication.principal` が `LoginUserContext` でない場合、actor type が不明な場合、または Cognito 設定が空の場合は `/login` へ戻す
- Cognito Managed Login Branding を PLATFORM / TENANT App Client ごとに分ける
- PLATFORM Hosted UI は赤系、TENANT Hosted UI は青系の primary button と page background にする
- `AppRuntimeStack` から ECS container へ `WORKOPS_COGNITO_HOSTED_UI_DOMAIN_BASE_URL` と `WORKOPS_COGNITO_LOGOUT_URI` を渡す
- `WORKOPS_COGNITO_LOGOUT_URI` は `${cloudFrontHttpsUrl}/login` に固定する

## ADR

- `POST /logout` を採用する。Spring Security の CSRF 保護に乗せ、第三者サイトからの強制 logout を避けるため。
- Spring 標準の `OidcClientInitiatedLogoutSuccessHandler` は採用せず、WorkOps 専用 handler を使う。Cognito `/logout` の `client_id` / `logout_uri` と PLATFORM / TENANT client id の選択を明示するため。
- logout 後は `/login` に戻す。入口別 logout 完了画面や即再ログインは作らない。
- Cognito Hosted UI の文字列変更は採用しない。Managed Login の branding editor は text を変更できないため、App Client ごとの色差分で判別性を作る。
- Cognito Trigger、Pre Token Generation、SSO、テナント別ログイン画面、本格ブランドデザインは作らない。
- Cognito claim、group、scope は業務権限の正本にしない。

## 対応範囲

- Cognito logout success handler
- Spring Security logout success handler 設定
- 共通 header の logout form
- Cognito Managed Login Branding の PLATFORM / TENANT App Client 差分
- CDK AppRuntimeStack の Cognito logout 用環境変数
- `.env.example` と README の Cognito 設定更新
- Java / template / CDK tests

## 除外範囲

- Cognito Trigger
- Pre Token Generation
- SSO
- テナント別ログイン画面
- 本格的なブランドデザイン
- Cognito group / scope による業務認可
- ユーザー作成、権限割当、ユーザー無効化の新規拡張
- AWS dev での実 login / logout 完了扱い

## 完了条件

- `/login` が通常利用者向けの TENANT login 開始画面として維持されている
- Cognito Hosted UI 上で TENANT / PLATFORM の見た目差分を判別できる
- `/login/tenant` と `/login/platform` の OAuth2 login 開始 redirect を維持している
- ログイン済みユーザーに logout button が表示される
- logout button は `POST /logout` と CSRF token を使う
- non-local profile の Spring Security logout success handler が Cognito logout URL へ redirect する
- logout URL は actor type に応じた App Client ID と `/login` logout URI を使う
- AppRuntimeStack が hosted UI domain と logout URI を ECS container environment へ渡す
- README が platform / tenant / logout 用 Cognito 設定に更新されている
